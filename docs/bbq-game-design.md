## 一、产品概述

### 1.1 产品定位

- **游戏名称**：烧烤大师（BBQ Master）
- **游戏类型**：堆叠三消 / 休闲益智
- **目标平台**：H5（微信小游戏 / 抖音小游戏 / 浏览器 Web）
- **目标用户**：18~40 岁，偏好休闲益智类游戏的移动端用户，尤其是对美食题材有亲切感的女性及轻度玩家
- **核心卖点**：在烟火气十足的烧烤摊场景中，通过点击解锁被遮挡的烤串，凑齐三串相同食材自动消除，轻松上手、越玩越上瘾

### 1.2 核心价值

| 维度 | 描述 |
|---|---|
| 趣味性 | 层叠遮挡带来"找到它、点击它"的解谜满足感 |
| 轻度休闲 | 单局 2~5 分钟，适合碎片化时间 |
| 视觉吸引 | 暖色调烧烤摊氛围，食材 Emoji 直观可爱 |
| 传播性 | 关卡通关截图、分数排行天然具备社交分享动机 |

### 1.3 竞品参考

- 羊了个羊（层叠消除机制）
- 疯狂烧烤摊（主题参考）
- 3 Tiles（底部托盘槽机制）

### 1.4 预计开发周期

| 阶段 | 内容 | 周期 |
|---|---|---|
| MVP | 核心玩法 + 前 20 关 + 基础 UI | 2 周 |
| 完整版 | 100 关 + 道具系统 + 音效动画 | 再 2 周 |
| 优化版 | 性能优化 + 分享 + 广告接入 | 再 1 周 |

## 二、核心玩法设计

### 2.1 游戏概念

屏幕中央摆放着若干烤盘，烤盘上堆叠着各种烤串。玩家通过点击可操作的烤串，将其送入底部的餐盘栏。餐盘栏中凑齐 3 个相同食材的烤串，三串自动消除并得分。餐盘栏共 7 个格子，格子全满且无法消除时游戏失败；消除关卡内全部烤串则通关。

### 2.2 详细操作流程

```
1. 关卡开始
   └── 系统根据关卡配置生成烤盘和烤串布局

2. 玩家点击烤串
   ├── 判断该烤串是否"可点击"（无其他烤串遮挡其超过 50% 面积）
   ├── 可点击 → 烤串飞入底部餐盘栏最右侧空格
   └── 不可点击 → 触发抖动动画，不执行操作

3. 餐盘栏检测
   ├── 每次新增烤串后，扫描栏内是否存在 3 个相同食材
   ├── 存在 → 三串高亮，执行消除动画，得分，后方烤串自动左移补位
   └── 不存在 → 检查栏内是否已满 7 格
       ├── 未满 → 等待玩家继续点击
       └── 已满且无可消除组合 → 触发失败流程

4. 胜利条件
   └── 关卡内所有烤串全部消除（烤盘区清空），触发通关流程

5. 失败条件
   └── 餐盘栏 7 格全满，且不存在 3 个相同食材可消除
```

### 2.3 层叠遮挡规则

遮挡规则是核心策略深度的来源，规则如下：

**遮挡判定**

- 每个烤串是一个矩形碰撞区域（约 60×60 px 逻辑单位）
- 烤串 A 在烤串 B 的上方层级（z-index 更高）且两者矩形重叠面积超过烤串 B 面积的 **30%**，则认定 A 遮挡 B
- 被遮挡的烤串呈半透明灰色（opacity: 0.45），且点击无效
- 未被遮挡的烤串高亮显示，可点击

**层级关系**

- 同一烤盘内，渲染层级由数据中的 `layer` 字段决定（0 为最底层，数值越大越靠上）
- 不同烤盘之间无遮挡关系，各烤盘独立计算
- 玩家移走上层烤串后，系统实时重新计算被遮挡状态

**图示**

```
烤盘示意（侧视层叠）：

  [🍖]  ← layer 2，可点击（无上层遮挡）
 [🌽][🍢] ← layer 1，被 🍖 遮挡部分区域，根据重叠比例判断
[🦐][🥩][🍗] ← layer 0，底层，被上层遮挡
```

**布局类型**

关卡数据中定义以下几种烤盘布局模板：

| 布局名称 | 形状描述 | 适用关卡 |
|---|---|---|
| 金字塔型 | 底3中2顶1，标准三角叠放 | 第 1~10 关 |
| 菱形 | 中间多、四边少的菱形结构 | 第 5~20 关 |
| 随机散铺 | 在固定网格坐标随机放置，有偏移 | 第 15 关以上 |
| 交叉叠加 | 多层横纵交替，遮挡复杂度高 | 第 30 关以上 |

### 2.4 餐盘栏规则

- 餐盘栏共 **7 个格子**，固定排列在屏幕底部
- 烤串从右侧第一个空格依次填入（插入到已有烤串右侧，不做排序）
- 消除发生时，被消除的 3 格空出，右侧烤串向左自动补位
- 同一时刻餐盘栏只有一种消除触发（不会连续消除），每次消除后重新检测
- 特殊情况：若消除后补位导致新的 3 消组合，则连锁触发，计连击分

### 2.5 核心游戏循环

```
点击烤串
  → 飞入餐盘
    → 触发消除 / 未消除
      → 继续点击 / 使用道具
        → 通关（清空烤盘）
          → 结算界面 → 下一关
        → 失败（餐盘满）
          → 失败界面 → 重试 / 看广告复活
```

## 三、关卡系统设计

### 3.1 难度曲线设计

关卡难度由以下四个参数综合决定：

| 参数 | 说明 | 低难度 | 中难度 | 高难度 |
|---|---|---|---|---|
| 食材种类数 | 同时出现的不同食材数量 | 3~4 种 | 5~7 种 | 8~10 种 |
| 烤串总数 | 关卡内烤串总数量（必须为 3 的倍数） | 18~27 | 30~45 | 48~60 |
| 层叠深度 | 最大层数 | 2 层 | 3 层 | 4~5 层 |
| 布局复杂度 | 遮挡关系密度 | 稀疏 | 中等 | 密集交叉 |

**关卡分段**

| 关卡段 | 关卡数 | 核心特征 |
|---|---|---|
| 新手段 | 第 1~5 关 | 3 种食材，最多 2 层，烤串 18 个，无干扰 |
| 入门段 | 第 6~15 关 | 4~5 种食材，3 层，烤串 24~33 个 |
| 进阶段 | 第 16~30 关 | 6~7 种食材，3~4 层，烤串 36~45 个，引入干扰格 |
| 挑战段 | 第 31~50 关 | 8~9 种食材，4~5 层，烤串 45~54 个 |
| 大师段 | 第 51~100 关 | 9~12 种食材，5 层，烤串 54~60 个，高复杂布局 |

### 3.2 关卡生成算法

关卡数据由算法自动生成，保证每关必然可解（每种食材数量严格为 3 的倍数）。

**生成步骤**

```
Step 1：确定参数
  - 根据关卡编号查关卡配置表，确定食材种类数 K、总烤串数 N、层叠深度 D
  - N 必须是 3 的倍数，K 通常在 3~12 之间

Step 2：生成食材列表
  - 从 12 种食材中随机选取 K 种
  - 每种食材分配数量 = N / K（若不能整除，则对部分食材 +3 补齐，确保仍为 3 的倍数）
  - 打乱食材列表顺序，得到待放置的烤串序列

Step 3：生成坐标布局
  - 根据布局模板生成各层坐标点集合
  - 将烤串随机分配到坐标点，记录每个烤串的 (x, y, layer, type)

Step 4：可解性验证
  - 模拟一次贪心求解：每轮优先取顶层可点击、且餐盘栏内已有同类型的烤串
  - 若模拟可以清空烤盘，则认为关卡可解
  - 若失败，重新 shuffle 食材分配（最多重试 50 次）
  - 极端情况下降低层叠复杂度重新生成

Step 5：序列化输出
  - 将关卡数据序列化为 JSON，存入关卡配置文件
```

**关卡数据结构示例**

```json
{
  "levelId": 5,
  "name": "第 5 关 · 烤串大会",
  "totalItems": 27,
  "ingredientTypes": 3,
  "maxLayer": 2,
  "trays": [
    {
      "id": "tray_1",
      "position": { "x": 0.2, "y": 0.3 },
      "items": [
        { "id": "item_001", "type": "ribs", "emoji": "🍖", "layer": 0, "gridX": 0, "gridY": 0 },
        { "id": "item_002", "type": "corn",  "emoji": "🌽", "layer": 0, "gridX": 1, "gridY": 0 },
        { "id": "item_003", "type": "ribs",  "emoji": "🍖", "layer": 1, "gridX": 0, "gridY": 1 }
      ]
    }
  ]
}
```

### 3.4 特殊关卡设计

每 10 关设置一个 Boss 关：

- **第 10 关（挑战关）**：限制道具使用次数为 0，烤串数量为常规的 1.3 倍
- **第 20 关（速度关）**：加入计时限制（120 秒内通关）
- **第 30 关（多盘关）**：烤盘数量增加到 6 个，布局更复杂
- **第 50 关（终极关）**：全部 12 种食材，5 层叠放，60 个烤串

## 五、道具系统

关卡中可使用三种道具，每种道具在开始关卡时有默认数量，使用完后需观看广告补充或通关后奖励获得。

### 5.1 道具列表

#### 撤回（Undo）

- **图标**：↩️
- **功能**：将餐盘栏中最后一个放入的烤串退回到原来的烤盘位置（不超过 3 步）
- **限制**：每关默认 3 次；不可撤回已消除的烤串
- **策略价值**：错误点击救场，是最常用的道具
- **动画**：餐盘栏最右侧烤串飞回原烤盘位置

#### 洗牌（Shuffle）

- **图标**：🔀
- **功能**：重新随机打乱当前烤盘区中所有**未消除**烤串的层级关系和位置
- **限制**：每关默认 1 次；洗牌后不改变食材总数和种类
- **策略价值**：陷入死局时的最后手段
- **动画**：所有烤串飞到屏幕中央旋转混合，再散落回烤盘

#### 移出（Remove）

- **图标**：🗑️
- **功能**：从餐盘栏中选择并移出 1 个烤串（移出后不消除，暂时存入"暂存区"，暂存区上限 1 个）
- **限制**：每关默认 1 次；移出的烤串关卡结束时消失，不退回烤盘
- **策略价值**：腾出关键格子，打破僵局
- **动画**：被移出的烤串向右飞出屏幕

### 5.2 道具补充规则

| 补充方式 | 获得道具 |
|---|---|
| 观看 15 秒激励广告 | 随机补充 1 个道具 |
| 通关奖励 | 下一关开始时自动恢复默认数量 |
| 失败复活 | 观看广告可复活，复活时餐盘栏清除最后进入的 3 个烤串 |

## 六、计分系统

### 6.1 基础分规则

每次消除 3 个相同食材得基础分，基础分与食材稀有度相关：

| 食材组 | 食材 | 单次消除基础分 |
|---|---|---|
| 普通档 | 🍖 🌽 🍢 | 100 分 |
| 进阶档 | 🦐 🥩 🍗 | 150 分 |
| 稀有档 | 🌶️ 🍠 🐙 | 200 分 |
| 传说档 | 🥦 🧅 🍄 | 300 分 |

### 6.2 连击加分

连击（Combo）定义：在不点击道具的前提下，**连续触发消除**（包括补位触发的连锁消除）计为连击。

| 连击数 | 连击倍率 | 提示文字 |
|---|---|---|
| 1 击 | ×1.0 | 无提示 |
| 2 连击 | ×1.5 | "Nice!" |
| 3 连击 | ×2.0 | "Great!" |
| 4 连击 | ×2.5 | "Awesome!" |
| 5 连击以上 | ×3.0 | "烧烤大师！" |

连击计数在以下情况重置：
- 玩家点击烤串但未触发消除
- 玩家使用任意道具
- 超过 3 秒未操作

### 6.3 通关奖励分

| 通关条件 | 额外分数 |
|---|---|
| 基础通关 | +500 分 |
| 餐盘栏剩余格子 ×200 分（最多 +1400） | 越干净越高分 |
| 未使用任何道具 | +1000 分 |
| 30 秒内通关 | +2000 分（速通奖励） |

### 6.4 分数展示

- 当前分数显示在顶部右侧，消除时数字滚动动画加分
- 连击提示文字从消除位置浮出，向上飘散消失
- 通关结算界面展示：本关得分 / 历史最高分 / 星级评价（1~3 星，按分数段划分）
- 三星标准：满分 = 基础通关分 + 全部快速消除理论最高分

### 7.2 各区域详细说明

**顶部导航栏（高度 56px）**

- 左侧：返回按钮（图标 + 文字"返回大厅"）
- 中间：关卡名称（"第 X 关"，字号 18px Bold）
- 右侧：当前分数（字号 20px，数字字体），旁边显示星级进度（三颗小星星）

**道具栏（高度 48px）**

- 三个道具按钮横排，每个按钮 80px 宽，包含图标 + 剩余次数角标
- 次数为 0 时按钮灰色，点击弹出"观看广告补充"弹窗
- 背景为半透明暖色木板纹理

**烤盘游戏区（高度约 420px）**

- 背景为烧烤摊场景插画（夜晚暖光、木炭炉子背景，静态图片）

## 八、动画效果设计

所有动画均通过 CSS Transition / CSS Animation / requestAnimationFrame 实现，不依赖重型动画库。

### 8.1 烤串飞入动画

- **触发**：点击可点击的烤串
- **效果**：烤串从当前位置沿贝塞尔曲线飞向餐盘栏目标格子
- **参数**：
  - 持续时间：200ms
  - 曲线：`cubic-bezier(0.25, 0.46, 0.45, 0.94)`（先快后慢，落入感）
  - 途中略微缩放（1.0 → 1.2 → 1.0），模拟弹跳落入
- **注意**：飞行途中该格子预留位置（虚影占位），防止视觉跳变

### 8.2 三消消除动画

- **触发**：餐盘栏检测到 3 个相同食材
- **效果**：
  1. 三格同时缩放 1.0 → 1.35，发出橙黄色辉光（50ms）
  2. 发射火花粒子（8 颗，向外扩散，150ms）
  3. 三格缩放至 0 并消失（100ms）
  4. 右侧格子向左平移补位（150ms，`ease-out`）
- **连击时**：额外显示连击文字从餐盘中央向上浮起（"2 COMBO!" 等），300ms 后淡出

### 8.3 不可点击反馈动画

- **触发**：点击被遮挡的烤串
- **效果**：烤串左右抖动（translateX ±4px，往复 3 次，总计 200ms）
- **辅助**：播放短促的"叮"提示音

### 8.4 通关动画

- **触发**：最后一批烤串消除，烤盘区清空
- **效果**：
  1. 烤盘区出现金色烟花粒子从下向上爆炸（持续 1.5s）
  2. 屏幕中央"通关！"大字从中间缩放弹出（scale 0 → 1.2 → 1.0，300ms）
  3. 星级评价动画：1~3 颗星依次"叮"的音效后亮起（每颗间隔 400ms）
  4. 弹出通关结算弹窗（延迟 1.5s 后出现）

### 8.5 失败动画

- **触发**：餐盘栏第 7 格被填满且无可消除
- **效果**：
  1. 餐盘栏整体红色闪烁 3 次（300ms/次）
  2. 全屏半透明红色蒙层淡入（500ms）
  3. "餐盘满了！"文字从上方落入屏幕中央（500ms）
  4. 弹出失败弹窗（延迟 800ms 后出现）

### 8.6 新食材解锁动画

- **触发**：首次进入含有新食材的关卡
- **效果**：新食材 Emoji 从屏幕中央放大弹出，背景烟花，显示食材名称和"解锁！"文字，2s 后自动消失

### 8.7 道具使用动画

- **撤回**：被撤回的烤串从餐盘栏飞回原烤盘位置（反向贝塞尔，250ms）
- **洗牌**：所有烤串向屏幕中央旋转汇聚（400ms）→ 旋转混合（300ms）→ 散落回烤盘（400ms）
- **移出**：选中烤串向右飞出屏幕外（300ms，加速曲线），伴随"嗖"音效

## 九、音效设计

所有音效使用 MP3/OGG 双格式，总包体控制在 500KB 以内（使用 Web Audio API 播放）。

### 9.1 音效列表

| 音效 ID | 触发时机 | 描述 | 时长建议 |
|---|---|---|---|
| `click_valid` | 点击可点击烤串 | 清脆的"嘿"声，模拟夹起烤串 | 0.2s |
| `click_invalid` | 点击被遮挡烤串 | 低沉短促"嗯"或金属碰撞声 | 0.2s |
| `slot_in` | 烤串落入餐盘格 | 木质"咚"落入声 | 0.15s |
| `match_3` | 触发三消 | 短促欢快的"叮叮叮" | 0.4s |
| `combo_2` | 2 连击 | "Nice!" 语音或上扬音调 | 0.3s |
| `combo_3` | 3 连击 | "Great!" 更高亢音调 | 0.3s |
| `combo_max` | 5+ 连击 | 欢呼声 + 烧烤滋滋声 | 0.8s |
| `level_clear` | 通关 | 欢快胜利旋律 | 2.0s |
| `level_fail` | 失败 | 低落短曲 | 1.5s |
| `tool_undo` | 使用撤回道具 | 倒带音效 | 0.3s |
| `tool_shuffle` | 使用洗牌道具 | 洗牌混合音效 | 1.2s |
| `tool_remove` | 使用移出道具 | 嗖飞出音效 | 0.3s |
| `star_unlock` | 星级亮起 | 单颗星"叮"声 | 0.3s |
| `ingredient_unlock` | 新食材解锁 | 欢快上扬短旋律 | 1.0s |
| `slot_warning` | 餐盘栏剩余 1~2 空格 | 低频警示音 | 0.5s |
| `bgm_game` | 游戏进行中背景音乐 | 轻松欢快的烧烤摊风格音乐（循环） | 60s loop |
| `bgm_menu` | 关卡选择/主界面 | 轻松 lo-fi 风格 | 60s loop |

### 9.2 音效实现要点

- 使用 Web Audio API 的 `AudioContext` 统一管理，避免 `<audio>` 标签多实例冲突
- 短音效（小于 0.5s）预加载到 AudioBuffer，点击时零延迟播放
- BGM 使用 `<audio>` 标签 loop 属性，支持淡入淡出切换（crossfade 500ms）
- 提供全局静音开关（顶部导航栏音量图标），状态存入 localStorage
- 首次用户交互后才初始化 AudioContext（浏览器自动播放策略限制）

### 10.2 渲染方案

**DOM + Canvas 混合渲染**

- **烤串元素（Ingredient Card）**：使用绝对定位的 DOM 元素（`<div>`），利用 CSS Transform 实现动画，简化触摸事件处理
- **粒子特效**：使用独立的 `<canvas>` 层叠在 DOM 之上，通过 `pointer-events: none` 不干扰点击
- **背景场景**：静态 CSS background-image，避免 Canvas 重绘成本

选择依据：纯 Canvas 方案在 Emoji 渲染、文字处理、可访问性方面不如 DOM 方便；混合方案兼顾动画性能和开发效率。

### 10.3 引擎选择建议

**推荐：Vanilla JS（无依赖）**

理由：
- 游戏逻辑相对简单，不需要物理引擎
- 避免引入 Phaser（压缩后约 1MB）、PixiJS（约 600KB）等重型库增大包体
- 直接使用 CSS Animation + requestAnimationFrame 足够流畅
- 更易在微信小游戏等平台适配

备选：若后期特效需求升级，可引入 **GSAP（约 60KB gzip）** 处理复杂动画时间轴。

### 10.4 性能指标
